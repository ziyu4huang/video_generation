## Findings

1. **[should-fix] `ground.ts` number gate is substring-based — hallucinated digits slip through.** `src/vlm/ground.ts:80` checks `haystack.includes(token)`. Empirically: `groundClaim("claim: 234 samples", "we evaluated 1,234 samples")` → `grounded:true`; `groundClaim("a 7B model", "the 17B baseline")` → `grounded:true`. Numbers are the *hard* gate (the only `grounded:false` flipper for the finding-4 class), so this is precisely the hallucination shape the module exists to catch — the test's `87%` vs `92%` fixture never exercises digit-subsumption. Fix: boundary-aware match, e.g. `new RegExp("(?<![\\d.,])" + escape(token) + "(?![\\d.,%A-Za-z])")` (Bun supports lookarounds), plus regression tests for `234`-in-`1,234` and `7B`-in-`17B`.
2. **[should-fix] The IngestSummary merge omits `cards`.** `extensions/knowledge-card.ts:1269–1282` sums counters, concats `dedupDecisions`/`parseErrors`, ORs `mocUpdated`, rewrites `sourceLabel` — but never merges `summary.cards` (`types.ts:178`), so a multi-file generic ingest's tool result `details: { ...summary }` (line ~1306) reports only the **first** group's `IngestCardReport[]`. `formatSummary` doesn't consume `cards` (human output correct), but `details.cards` is an established tool-result contract in this package (`__tests__/e2e-orchestration.test.ts:366,376,397`), and `extract.ts:623` / `distill/converge.ts:118` consume it from direct `ingestRecords` calls. One line: `summary.cards.push(...s.cards)`.
3. **[nit] `isCaptionFigure` can fire on colon-bearing prose.** Empirically `isCaptionFigure("As shown in Figure 1: the curve flattens…")` → `true` — a prose colon reference inside a ≤3000-char page triggers a vision attempt. Mitigations are real (band + measured 9/9 fired, 0 false positives on the corpus; consequence is only extra cost, degrade-not-throw holds), so acceptable — but the new test named "prose references never fire" only covers *non-colon* prose and overstates the guarantee. A line-start anchor (`^Figure\s+\d+\s*:` with `m`) may or may not survive two-column PDF extraction — if hardening, measure first.
4. **[nit] `recordLabels` misalignment trap in the default lane.** `extensions/knowledge-card.ts:1232–1235` — the `workflow-jsonl` branch pushes records without a matching `recordLabels.push(...parsed.records.map(() => null))`. Benign today (single lane per invocation, `?? defaultLabel` backfills the undefined tail), but any future mixed-label lane silently shifts indices. Add the symmetric push.
5. **[nit] Named-run soft check is also substring:** `"RAG Flow"` grounds via page text `"a drag flow diagram"` (empirical). Soft-suspect direction only (numbers are the hard gate), so low priority; the finding-1 lookaround fix covers this too if applied to named runs.
6. **[nit] Stale docblock.** `src/adapters.ts:455–456` — `adaptGenericMarkdown`'s header mapping still advertises `tags = … ∪ [[wikilinks]] ∪ …`, contradicting the D4 removal implemented 70 lines below. Update the comment.
7. **[nit] Behavior change beyond the stated hard rules:** all-inputs-fail now returns `isError` `no_records` (`knowledge-card.ts:1285–1292`) where the old path called `ingestRecords([])` and returned a zero-summary. It's an improvement (explicit failure, still no throw) — just note it wasn't in the "legacy preserved" list.
8. **[nit] Per-group `scheduleCardRebuild`:** N label groups → N `indexRebuild` schedules; coalescing (`surreal-index.ts:496–531`) only covers in-flight overlap, and the fire-and-forget + D36 freshness gate keep this non-blocking. Batch to one rebuild after the loop if rebuild cost ever shows up in receipts.
