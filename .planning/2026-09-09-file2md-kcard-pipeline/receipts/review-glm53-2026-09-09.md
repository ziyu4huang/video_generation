# Review: file2md → kcards pipeline + benchmark design

Method note: per the operating method ("read the actual artifact"), I verified every checkable card claim against the on-disk page-md rather than trusting the task description's "numbers copied from page-006". That distrust was justified — it caught a falsified number set. No deploy-bundle learning applied (no deployed-tree divergence here); this was pure source-artifact reading.

## 1. Verdict

**REWORK** — one card contains falsifiable number misattribution (knowledge corruption), and the direct-write bypass left the cards invisible to the retrieval layer (verified: absent from the semantic index and graph notes).

## 2. Findings

**1. [blocking] ReCite card: "Table 3 strict end-to-end" numbers are a cross-table composite — misattributed metrics.**
Card claims: *"主要結果（Table 3，strict end-to-end）：ReCite-SFT(CAP-8)（僅 4B）Overall F1 89.71，對比 GPT-5.1-Chat（direct prompting）的 37.81。Optional citation 的 F1…55.14 vs 15.92"*
Against `output/kcard-papers/md/2609.09156/pages/page-006.md`:
- **89.71 is the Position-Only F1**, not Overall-Strictly. The actual strict end-to-end F1 for ReCite-SFT(CAP-8) is **39.15**.
- **37.81 is from Table 4** (citation *location* prediction, GPT-5.1-Chat Direct Overall) — a different task and table. Table 3's end-to-end GPT-5.1-Chat Overall-Strictly F1 is **10.32**.
- **55.14 is the Lenient F1** (Table 3); **15.92 is Table 4's Optional** (location). "Optional" columns don't exist in Table 3 at all.
The honest comparison (39.15 vs 10.32, ~3.8×) is still dramatic — but the card as written compares Position-Only against a location-prediction number and labels both "strict end-to-end", inflating ~2.3× and mixing two evaluation tasks. Irony noted: the paper's own thesis is misattribution of real sources.

**2. [blocking] Convergence bypass confirmed at the index layer — the 3 cards are unreachable by the tools that are supposed to read them.**
- `vaults_root/s2-agent-vault/.knowledge-semantic/text-embedding-nomic-embed-text-v1-5.json`: grep for `ReCite|SPINE|Procedural Graphs` → **0 hits**. Not embedded → `zk_ask` seed retrieval cannot surface them.
- `Zettelkasten/knowledge-graph/` (2,352 notes): **no** graph note for any of the 3 cards (the one "spine" hit is an unrelated `Run-Pipeline-Driver-Spine…` card).
- 4-layer dup check and canonical-id upsert (`zk_card add`, per `skills/using-knowledge-cards/SKILL.md` — "zk_ingest DEFAULT… idempotent by canonical id") all skipped. Consequences: query recall silently zero for these cards; a future properly-ingested card on the same paper will coexist as a near-dup; hotness/merge operate on an index that doesn't know these files. Fix now: run `zk_ingest generic` over the 3 files (idempotent upsert), and add an orphan detector to `zk_card check` (card file present, absent from index → flag) so the bypass class is detectable, not just avoidable.

**3. [should-fix] Procedural Graphs card: "跨 6 個 benchmark" — the source lists 7.**
`page-021.md:39-42` (Table 7): HotpotQA, MultiChallenge, GDPval, ALFWorld, τ-bench, BFCL v3, **EnterpriseArena** = 7. Count errors are the cheapest corruption to prevent and the cheapest to gate (deterministic).

**4. [should-fix] Vision descriptions folded into 證據 with no grounding check — the missing guard the SKILL itself prescribes.**
`.planning/2026-09-08-file2md-svg-pptx-vision/map.md` (ADR-0001 posture, D4/D16): vision is an *interpretation layer*, receipts record model — never ground truth. The cards do label provenance ("glm-5.3-flash 視覺描述，file2md 轉換") — good. And in the one case I could check, the vision output was text-verifiable: the "相似度 92%" in `fig-2609.09156.md` appears verbatim in the page-001 text layer (line 89: `Similarity Score: 92% (High Overlap)`). But *nothing enforced* that: a hallucinated number would have sailed into 證據 identically. Missing guard: a deterministic number/entity-overlap check of vision bullets against the page text layer (born-digital figures embed their labels as text — exactly this fixture class), plus judge entailment for the rest.

**5. [should-fix] Provenance is unauditable after `git clean`.**
Cards cite `sources: ["arXiv:2609.09156"]`, but pages/, fig-*.md, and the PNGs live under gitignored `output/kcard-papers/`. Post-clean, finding 1 could not be re-caught from the repo. (Same trap class as operating-learning 2 — the label `arXiv:<id>` is not the evidence.) Fix: the benchmark commits its fixture corpus (below); cards should carry evidence anchors (`Table 3, p.6` — the ReCite card does name Table 3, which is precisely *why* the error was findable; promote that to a schema convention: every number bullet names its table/figure + page).

**6. [nit] SPINE card: "24 條謬誤戰術（Ethos 7 / Logos 10 / Pathos 6 / 直接質疑對照 1）" mislabels the control as a fallacy tactic** — Table 4's caption (page-007) says "full MAFALDA-**23** menu"; the direct-challenge is a control arm, not tactic #24. Say "23 tactics + 1 control". (All four SPINE numbers — CR@5 50%, CR@25 92%, Haiku-proxy 76%, 4-tactics 81% — **verified correct** against Table 4, page-007. Credit where due.)

**7. [nit] Structural compliance is otherwise fine.** Frontmatter shape (id `YYYYMMDDHHmm`, created, tags[], sources[]) matches house cards (e.g. `Bug Pattern - Holistic VLM Score…` id `202607040001`); sections 核心想法/證據・脈絡/連結 present; `[[Tags/Index]]` resolves (`vaults_root/s2-agent-vault/Tags/Index.md` exists); all 3 cross-links resolve. `card-format.ts` `readCardMeta` tolerates the missing `source_id`/`status`/`confidence` (default-light by design), though link computation then runs on tags only — another quiet cost of the hand-write path.

**8. [nit] Coverage bias:** 3 same-day cs.CL papers, hand-picked "interesting", 1 card each. Fine for a smoke run; fatal as a benchmark fixture (it exercises only born-digital text-provenance pages — smart's figure heuristic fired 0 times, so the vision lane was never actually stressed *through the pipeline*; the fig descriptions came from a hand-rolled script around the same seams).

## 3. Benchmark design — `bench-kcards`

**Home: new workspace package `bun-apps/bench-kcards/`** (plain package, NOT an `s2-agent-ext-*` extension — no registry entry, no `extensions/` file). Rationale: the bench spans two ext packages (file2md extraction/vision seams, knowledge-card zk_* tools); nesting it in either creates an upward or cross-tier dependency (`knowledge-card` would need `file2md`; tiering says edges point down only — SKILL.md's own ADR-0001 rule). A neutral bench package depends on both lib faces (`@repo/s2-agent-ext-file2md`, `@repo/s2-agent-ext-knowledge-card`) with zero back-edges. Two run modes:
- `bun test` — deterministic lanes only (no network), CI-safe.
- `BENCH_LIVE=1 bun run bench` — vision (capabilities.vision = zai/glm-5.3-flash) + judge (zai/glm-5.3) lanes, writing a live receipt — the archify/file2md skiplisted-receipt precedent (`receipts/live-vision-2026-09-08.md`).

**Critical rig rule: never touch the real vault.** The vault is a submodule; the bench copies `vaults_root/s2-agent-vault` to a tmp dir (`BENCH_VAULT=$(mktemp -d)`; cp -r) and points every zk_* call at the copy. Planted dup cards and golden answers must never leak into the shipped vault.

### Phase 0 — fixture corpus + golden annotations

- **Goal:** frozen, committed, stratified inputs + ground truth independent of the pipeline under test.
- **Inputs/fixtures:** the 3 existing PDFs moved from `output/kcard-papers/` into `bench-kcards/fixtures/papers/` (committed — arXiv PDFs, ~1–5 MB each; reproducibility beats size), **plus 2**: one figure-heavy paper (forces smart's `isTextFigure` band to actually fire) and one scanned/OCR-dependent PDF. Total 5 papers, ~35–60 pages.
- **Golden authoring protocol (anti-leak):** `golden.json` per paper, written by a *fresh judge session reading only the independently re-extracted PDF text* (pdfjs direct, not file2md output), then human spot-check of 20%: (a) numeric claims as verbatim quotes with `page` + `table/figure` anchor; (b) K=8 QA pairs answerable **only** from pages, each answer with a page citation; (c) 2 unanswerable-but-plausible questions per paper; (d) figure-grounding claims keyed to a page raster.
- **Done-when:** fixtures committed, golden.json validates against a schema (anchors resolve to real page numbers), human spot-check sign-off recorded in the receipt.

### Phase 1 — build side

| Lane | Method | Metrics + thresholds | Cost |
|---|---|---|---|
| **1a Extraction faithfulness** | Deterministic proxy vs independent pdfjs re-extraction: (i) number-token recall/precision (every decimal in reference found in page-md); (ii) 20+-char span coverage; (iii) golden-table row survival. Judge (glm-5.3) rubric 0/1/2 on structure+reading order, sampled pages only (p1, table pages, figure pages) | number recall ≥ 0.98 (born-digital), span coverage ≥ 0.95, table row survival ≥ 0.95, judge mean ≥ 1.5, zero pages at 0 | 0 LLM for proxies; ~25 judge calls |
| **1b Vision grounding** | Split each fig-description into atomic claims; deterministic pre-check: every number/entity in a vision bullet must appear in page text layer or raster OCR; then judge entailment vs (raster + page text): SUPPORTED / NOT-SUPPORTED / UNVERIFIABLE | grounded-claim ratio ≥ 0.90; **any** vision-claim number absent from text+OCR = blocking hallucination flag (catches the class finding 4 guards) | ~8 rasters × ~6 claims ≈ 48 flash-judge calls |
| **1c Card structural compliance** | Deterministic on tmp vault: frontmatter keys, id `^\d{12}$`, section presence, wiki-link resolution (incl. hub), sources non-empty, evidence anchors (table/figure + page) on every numeric bullet | 100% pass, runs in plain `bun test` | 0 |
| **1d Card faithfulness** | Each card bullet → judge must return supporting span `{page, quote}`; graded SUPPORTED / **MISATTRIBUTED** (numbers real but wrong table/metric — the finding-1 class) / UNSUPPORTED. Judge output IS the spot-check citation | faithfulness ≥ 0.95; **MISATTRIBUTED = 0** (hard gate) | ~60 claims × 1 judge call |
| **1e Dedup effectiveness** | Plant N=10 near-dup cards (4 exact, 3 light-paraphrase, 3 heavy) into tmp vault via `zk_card add` + `zk_ingest generic`; count catches per layer | exact+light catch ≥ 0.90 (report heavy separately) | 0 LLM |

### Phase 2 — query side

| Lane | Method | Metrics + thresholds | Cost |
|---|---|---|---|
| **2a Golden QA** | From phase 0: 8/paper answerable + 2/paper unanswerable; answers authored page-only with citations; independent second model verifies answerability | set frozen, hash-pinned in receipt | (authored once) |
| **2b zk_ask scoring** | Run each question through `zk_ask`; judge grades vs golden: FAITHFUL+CITED / FAITHFUL-UNCITED / HALLUCINATED / REFUSED. Unanswerable: refusal = pass, confident answer = fail | faithful ≥ 0.80, hallucinated = 0, cite-right-card ≥ 0.75, refusal-on-unanswerable ≥ 0.80 | ~50 questions × (1 ask + 1 judge) |

### Cost / runtime estimate

~150 LLM calls total (8 vision + ~48 grounding-judge + ~25 extraction-judge + ~60 card-faithfulness + ~50×2 QA), ~2–4k in / ~300 out each ≈ **~600–800k tokens, one coffee (~10–15 min serial, ~5 min at concurrency 4)**. Deterministic lanes: seconds, free, CI-safe.

## 4. Build order (max signal per token)

1. **Fix the two blockings first** (they'd poison every baseline): re-run `zk_ingest generic` over the 3 cards into the real vault; correct the ReCite card's Table-3/4 numbers (39.15 vs 10.32 strict; optional→lenient relabel) and the 6→7 benchmark count. Re-embed.
2. **Phase 1c structural compliance** (deterministic, zero LLM) — cheapest possible gate, catches format drift forever.
3. **Phase 1a deterministic proxies** (number recall, span coverage, table survival) — no LLM, and number recall alone would have caught findings 1 and 3.
4. **Phase 2d + 2c** (MRR + tag recall on the tmp vault) — deterministic once embedded; turns the finding-2 bypass class into a permanent red gate.
5. **Phase 1d card faithfulness judge** — directly targets the MISATTRIBUTED class with citations as output.
6. **Phase 2b zk_ask scoring**, then **1b vision grounding** (deterministic overlap pre-check before any judge call), then **1e dedup**.
7. **Phase 2e**: wire gates + scorecard, record the first accepted live receipt, and add the `zk_card check` orphan detector so direct writes can never again be silent.
