# Claude Code TUI — Research Digest

## 1. Rendering stack

Claude Code was originally built on **Ink** (React renderer for terminals, Yoga flexbox layout), then "forked it beyond recognition" — the fork lives in-tree (`src/ink/`, ~48 files/~620KB: `ink.tsx`, `reconciler.ts`, `renderer.ts`, `dom.ts`, `screen.ts`, `screens/REPL.tsx` ~874KB) (https://claude-code-from-source.com/ch13-terminal-ui/, https://openedclaude.github.io/claude-reviews-claude/chapters/14-ui-state-management). Anthropic engineer Thariq Shihipar's Feb 2026 thread framed it as "a small game engine": per frame it constructs a scene graph with React → layout → rasterize to a 2D cell screen → diff vs previous screen → emit ANSI; ~16ms frame budget, ~5ms from scene graph to ANSI (https://blog.bigls.net/post/claude-code-game-engine-dx-bloat); Claude Code team member Chris Lloyd posted the same pipeline description (https://simonwillison.net/2026/Jan/22/chris-lloyd/, https://news.ycombinator.com/item?id=46755209).

Current runtime: a **custom React host via `react-reconciler` running `ConcurrentRoot`** (Suspense for lazy syntax highlighting), reconciling into a custom DOM of 7 element types (`ink-root`, `ink-box`, `ink-text`, `ink-virtual-text`, `ink-link` via OSC 8, `ink-progress`, `ink-raw-ansi`), then Yoga layout, cell-buffer rasterization, cell-level diff, patch optimization, one `stdout.write` wrapped in synchronized-update markers (BSU/ESU, DEC 2026) (https://claude-code-from-source.com/ch13-terminal-ui/). Frame scheduling: lodash `throttle` at 16ms (leading+trailing) via `queueMicrotask` (after layout effects), a separate 4ms fast path for scrolls that bypasses React entirely, double-buffered `Screen` frames, packed `Int32Array` cells (2 words/cell) with interning pools (Char/Style/Hyperlink) reset every 5 min (https://claude-code-from-source.com/ch13-terminal-ui/). Why they moved: stock Ink allocates ~1 object per cell per frame (24k objects/16ms on 200×120), string-level row diffs, no dirty tracking/blit — causing flicker and GC pauses; fixes (cell-level diffing ≈85% flicker reduction, packed typed arrays, upstream synchronized-output contributions to VS Code terminal/tmux) were described by Shihipar (https://claude-code-from-source.com/ch13-terminal-ui/, https://blog.bigls.net/post/claude-code-game-engine-dx-bloat). Newer versions add an optional **fullscreen renderer** (DEC 1049 alt-screen, mouse support; `/tui` reports which renderer is active) alongside the classic inline one (https://code.claude.com/docs/en/interactive-mode, https://claude-code-from-source.com/ch13-terminal-ui/).

## 2. Streaming output

Tokens arrive 10–50/s; re-parsing whole messages is avoided via (a) a 500-entry LRU cache of `marked.lexer()` results keyed by content hash, (b) a `hasMarkdownSyntax()` fast path (single regex over first 500 chars → plain-text token, ~3ms saved), and (c) **Suspense-lazy `cli-highlight`**: code renders unstyled instantly, colors pop a frame later (lib load 200–300ms, 50–100ms per 100-line block). A distinct `StreamingMarkdown` component tolerates unclosed fences/bold markers mid-stream, then swaps to the strict static GFM renderer on completion. Pre-highlighted code is carried in `ink-raw-ansi` nodes with known dimensions — zero re-parse cost (https://claude-code-from-source.com/ch13-terminal-ui/). Completed tool calls render as collapsed cards: Edit/Write show a **structured unified diff** with green `+`/red `-` hunks and context lines (`StructuredDiffList`, `countLinesChanged`, "Updated <path> with N additions, M removals") (https://github.com/claude-code-best/claude-code/blob/91cffe16/src/components/FileEditToolUpdatedMessage.tsx, https://github.com/davccavalcante/claude-code-leaked/blob/64646773/src/tools/FileEditTool/UI.tsx).

## 3. Input editor

Multiline input via `\`+Enter, Option+Enter, native Shift+Enter (supported terminals), `Ctrl+J`, or just pasting (https://code.claude.com/docs/en/interactive-mode). Full readline emulation: `Ctrl+A/E/K/U/W/Y`, `Alt+B/F/D`, `Alt+Y` paste-history cycling, `Ctrl+_` undo; word-boundary rules distinguish `Ctrl+W` (whitespace-run) from `Alt+B` (punctuation-split words) (https://code.claude.com/docs/en/interactive-mode). Optional **vim mode** (NORMAL/INSERT/VISUAL, motions `f{char}`/`t{char}`, text objects `iw`/`i"`, `vimInsertModeRemaps` like `jj`→Esc), state preserved across panel toggles (https://code.claude.com/docs/en/interactive-mode). **Paste**: long/multiline pastes collapse to a `[Pasted text #1]` chip; full content is sent on submit and re-recalled with history; bracketed-paste mode (2004) is used (https://github.com/anthropics/claude-code/issues/11033, https://github.com/anthropics/claude-code/issues/29375, https://github.com/anthropics/claude-code/issues/24418). **History**: per-working-directory, up-arrow reaches past sessions, consecutive duplicates collapse; `Ctrl+R` reverse search (inline in classic renderer; a scope-cycling dialog in fullscreen) (https://code.claude.com/docs/en/interactive-mode). **Slash autocomplete**: `/` opens a filtered menu (built-ins + skills + plugin/MCP commands); mid-prompt `/xyz` shows ghost-text completion with a `+N` overflow count outside fullscreen (Tab accepts), or a mouse-clickable list in fullscreen (https://code.claude.com/docs/en/interactive-mode). Matching is **fuzzy** — Fuse.js over command name parts + description words, subsequence-style (https://github.com/claude-code-best/claude-code/blob/632f3e19/src/utils/suggestions/commandSuggestions.ts, https://github.com/anthropics/claude-code/issues/65956). **`@` triggers file-path completion** (dropdown of matches, also suggests live cross-session agents); `!` shell mode adds slash-triggered path autocomplete (https://code.claude.com/docs/en/interactive-mode).

## 4. Keybindings and interrupts

`Esc` interrupts mid-turn keeping completed work (and flushes queued messages); `Esc Esc` clears the draft (saving it to history) or, on empty input, opens the **rewind/checkpoint menu** (hardcoded, not rebindable) (https://code.claude.com/docs/en/interactive-mode, https://github.com/anthropics/claude-code/issues/43717). `Ctrl+O` toggles the **transcript viewer** (expanded tool usage, timestamps, model per message; `Ctrl+E` show-all); `Ctrl+R` is history search; `Ctrl+B` backgrounds Bash/agents (twice under tmux); `!` enters shell mode; `Shift+Tab` cycles permission modes default→acceptEdits→plan→bypassPermissions→auto; `Ctrl+C` interrupt/clear/exit, `Ctrl+D` 800ms-confirmed exit, `Ctrl+L` redraw, `Ctrl+T` todo toggle, `Ctrl+G` external `$EDITOR` (https://code.claude.com/docs/en/interactive-mode). The `#` memory shortcut from early releases is no longer in the quick-prefix list (`/`, `!`, `@`, `:`, `?`); memory is now `/memory` (https://code.claude.com/docs/en/interactive-mode).

## 5. Status surfaces

During a turn a single **spinner line** like `✳ Infusing… (esc to interrupt · 5s · ↓ 217 tokens · thinking)` updates in place: rotating glyph (`· ✢ ✳ ✶ ✻ ✽`), one random playful verb chosen per turn, elapsed seconds, token counter, thinking indicator (https://github.com/anthropics/claude-code/issues/16578, https://www.stepcodex.com/en/issue/feature-match-terminal-spinner-verb-behavior-in-vs-code, https://github.com/Ladbaby/picc-working-spinner). A **context meter** appears near the threshold: `Context left until auto-compact: 17%` / `Context low (7% remaining) · Run /compact` (https://github.com/anthropics/claude-code/issues/44924, https://github.com/anthropics/claude-code/issues/9636). A customizable **statusLine** runs any shell command; session JSON arrives on stdin, stdout becomes the bar (ANSI allowed); `/statusline` generates one (https://code.claude.com/docs/en/statusline, https://claudelab.net/en/articles/claude-code/claude-code-status-line-customization-recipes). The bottom bar also shows the permission-mode indicator, e.g. `⏸ plan mode on` / `⏵⏵ accept edits on` (https://dev.to/rulestack/claude-code-plan-mode-what-it-actually-blocks-what-still-runs-and-what-approving-switches-you-22m3).

## 6. Queued/steering input

Typing + Enter while Claude works **queues** the message; queued entries are listed above the input box. Messages are injected **as soon as the current tool calls finish, within the same turn** (steering at tool boundaries); queued `!` commands and most slash commands wait for turn end. `Up` from the input's first row takes back queued items for editing; `Esc` interrupts and sends them immediately (https://code.claude.com/docs/en/interactive-mode, https://github.com/anthropics/claude-code/issues/36326, https://github.com/anthropics/claude-code/issues/71726).

## 7. Live progress surfaces

Subagent (Task) runs show live progress lines and an aggregate "(running)" status; backgrounded agents/shells surface via `/tasks` (https://code.claude.com/docs/en/interactive-mode, https://github.com/anthropics/claude-code/issues/32626). The **todo/task checklist** renders in the status area as a bordered panel with `[x]` done / `[>]` in-progress / `[ ]` pending rows, updated live; `Ctrl+T` toggles it (https://kotrotsos.medium.com/claude-code-internals-part-11-terminal-ui-542fe17db016, https://code.claude.com/docs/en/interactive-mode). **Plan mode** blocks writes until the plan is approved via an `ExitPlanMode` prompt (https://automatelab.tech/blog/ai-coding/how-claude-code-plan-mode-works/). **Permission prompts** are numbered choice lists — `1. Yes  2. Yes, and don't ask again for <scope>  3. No` — navigable by arrow keys (`❯` cursor), number keys, or Enter; `Tab` opens a per-answer comment field; `Esc` = No (https://code.claude.com/docs/en/permissions.md, https://github.com/anthropics/claude-code/issues/47201, https://github.com/anthropics/claude-code/issues/28139).

## 8. Print mode vs interactive

`claude -p` runs headless: no TUI, prompt from argv/stdin, single result. `--output-format` selects `text` / `json` (one result object with cost, usage, session_id) / `stream-json` (NDJSON event stream: `system/init`, assistant/user blocks, tool results, final `result`), with `stream-json` requiring `--verbose`; `--include-partial-messages` adds token-level `stream_event` deltas; the SDK supports persistent resumable streams (https://gist.github.com/TealOcean/96bb9276c2a4efa60351aaf9ab2eb4c8, https://github.com/takelushi/claude-code-rs/blob/de23ac359c3bd246e6b2573859f24151a3f9f61c/docs/claude-cli.md, https://docs.rs/claude-code/latest/claude_code/struct.ClaudeClient.html).

## TUI signature affordances

- Single in-place spinner line: rotating glyph + whimsical verb + `(esc to interrupt · Ns · ↓N tokens · thinking)`.
- Token-by-token streaming markdown that upgrades to full styling on completion; syntax colors pop in a frame later.
- Collapsible tool-call cards: diff with green `+`/red `-` hunks, file path, additions/removals counts.
- Esc interrupts gracefully (work kept); Esc-Esc opens a rewind/checkpoint menu.
- Shift+Tab mode ring with a persistent footer badge (`plan mode on`, `auto-accept edits on`).
- Queue messages while the model works, listed above the input, delivered at tool boundaries; Up reclaims them.
- Permission dialogs as numbered yes / yes-don't-ask-again / no lists with arrow-key cursor + Tab comment.
- Live bordered todo checklist with `[ ]/[>]/[x]` rows in the status area.
- `/` slash-menu with fuzzy (Fuse-style) matching, ghost-text completion + `+N` count; `@` file-mention dropdown.
- Large/multiline paste collapses to a `[Pasted text #N]` chip.
- `Ctrl+O` transcript viewer expanding every tool call with timestamps and model per message.
- `Ctrl+B` backgrounding of running Bash/agents; `/tasks` roster of background work.
- Customizable status line: JSON on stdin → one ANSI line out.
- Context meter (`context left until auto-compact: N%`) near the auto-compact threshold.
- `!` bash mode adding command output directly to context; optional vim input mode with `jj`-style remaps.
