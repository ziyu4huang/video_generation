# Claude Code — function/architecture digest

## 1. Core agent loop
One loop, one flat history: CC is a single "agentic harness" cycling **gather context → take action → verify results** until done (https://code.claude.com/docs/en/how-claude-code-works; https://www.anthropic.com/engineering/building-agents-with-the-claude-agent-sdk). Reverse-engineering confirms a single `queryLoop()` while-loop — one model call per turn, execute tools, feed results, loop (https://brain.xiaoquisme.com/sources/books/claude-code-from-source/claude-code-from-source-ch05); network capture shows "just one main thread" with a flat message list and no multi-agent graph (https://minusx.ai/blog/decoding-claude-code/). Mechanically Claude emits `tool_use` blocks; the harness executes each and returns output as `tool_result` blocks appended to the same history (https://platform.claude.com/docs/en/agents-and-tools/tool-use/bash-tool). Safe consecutive tool calls are batched concurrently (cap ~10); unsafe ones run serially (https://github.com/CodingCodingK/claude-code-report/blob/master/README.md). A turn ends on a text-only response; `Esc` cancels the running tool call immediately, typed lines queue and steer the next step; a smaller Haiku-class model handles >50% of internal calls (labels, file parsing, summaries) (https://code.claude.com/docs/en/how-claude-code-works; https://minusx.ai/blog/decoding-claude-code/).

## 2. Tool inventory & design
Canonical tool list (names used by permission rules/hooks): `Agent, Bash, Read, Edit, Write, Glob, Grep, NotebookEdit, WebFetch, WebSearch, TodoWrite, AskUserQuestion, EnterPlanMode/ExitPlanMode, EnterWorktree/ExitWorktree, Monitor, CronCreate/List/Delete, LSP, Skill, mcp__server__tool…` (https://code.claude.com/docs/en/tools-reference). MinusX's captured prompt: low-level (Bash/Read/Write), mid (Edit/Grep/Glob/LS), high (Task/WebFetch/ExitPlanMode) — plus `mcp__ide__getDiagnostics` (https://minusx.ai/blog/decoding-claude-code/).
- **Bash**: runs in one persistent bash process — cwd, env, files persist across calls (https://platform.claude.com/docs/en/agents-and-tools/tool-use/bash-tool). Per-call `timeout`; `run_in_background:true` returns a reference ID immediately, output polled later (https://michaeldishmon.com/writing/background-agents-run-in-background; https://github.com/anthropics/claude-code/issues/88702). OS sandbox via macOS Seatbelt (`sandbox-exec`) / Linux bubblewrap+socat: read-mostly FS + SOCKS5 network allowlist; with sandbox on, `autoAllowBashIfSandboxed` (default true) auto-approves Bash (https://code.claude.com/docs/en/sandboxing; https://code.claude.com/docs/en/permissions).
- **Read**: absolute path in, `cat -n` line-numbered output, default 2000-line / ~25k-token page with `offset`/`limit` paging and PARTIAL-view notice; reads images/PDFs/notebooks (https://dev.to/_94be737e156beb4d74df2/claude-code-tools-deep-dive-5-read-2ba6; https://github.com/anthropics/claude-code/issues/73281; https://www.developersdigest.tech/guides/read-tool).
- **Edit**: exact-string replace; `old_string` must match verbatim and be unique unless `replace_all`; read-before-edit enforced (error otherwise); non-unique → add context, or fallback to Write; MultiEdit now legacy/merged (https://github.com/Piebald-AI/claude-code-system-prompts/blob/main/system-prompts/tool-description-edit.md; https://dev.to/_94be737e156beb4d74df2/claude-code-tools-deep-dive-6-edit-243f; https://code.claude.com/docs/en/permissions).
- **Glob/Grep**: ripgrep-based LLM search, deliberately no embeddings/RAG (https://minusx.ai/blog/decoding-claude-code/; https://www.anthropic.com/engineering/building-agents-with-the-claude-agent-sdk).
- **WebFetch**: permission is domain-scoped (`WebFetch(domain:x)`) with preapproved docs domains; **WebSearch** asks per repo (https://code.claude.com/docs/en/permissions).
- **TodoWrite**: full-state todo list the model rewrites itself, nudged by `<system-reminder>` (https://minusx.ai/blog/decoding-claude-code/).

## 3. Permissions, settings, hooks
Rules `Tool` / `Tool(specifier)` in `permissions.{allow,ask,deny}`; evaluation order **deny → ask → allow, first match wins**; bare-tool deny removes the tool from context entirely; Bash rules match subcommands split on `&&`,`||`,`;`,`|` with wrappers (`timeout`,`nice`,`xargs`,env assignments) stripped; built-in read-only commands (`ls`,`cat`,`grep`,`git log`…) never prompt; redirection targets are checked as file writes; Read/Edit paths use gitignore-style `//`,`~/`,`/` anchors (https://code.claude.com/docs/en/permissions). Settings precedence: **managed/enterprise > CLI flags > `.claude/settings.local.json` (project-local) > `.claude/settings.json` (project, shared) > `~/.claude/settings.json` (user)**; deny at any level is absolute; project `allow` rules require workspace-trust acceptance (https://code.claude.com/docs/en/permissions; https://code.claude.com/docs/en/settings). Modes: `default` (ask), `acceptEdits` (auto file edits + mkdir/touch/mv/cp), `plan` (read-only research), `auto` (classifier auto-approves with background safety checks), `dontAsk`, `bypassPermissions`; `defaultMode` in settings, Shift+Tab cycles (https://code.claude.com/docs/en/permissions; https://code.claude.com/docs/en/permission-modes). Hooks: JSON-in/JSON-out shell commands in settings keyed by event — `PreToolUse/PostToolUse` (per tool call), `UserPromptSubmit`, `Stop`/`StopFailure`, `PreCompact`, `SessionStart/SessionEnd`, `Notification`, `PermissionRequest` — with regex **matchers** on tool names (`"Write|Edit"`) (https://code.claude.com/docs/en/hooks; https://code.claude.com/docs/en/agent-sdk/hooks). Exit code 2 blocks a tool call (even overriding allow rules); stdout JSON controls execution: `hookSpecificOutput.permissionDecision: allow|deny|ask`, `updatedInput`, `additionalContext`, `systemMessage`, Stop-hook `continue:false`+`stopReason` (https://code.claude.com/docs/en/hooks-guide; https://github.com/anthropics/claude-code/blob/main/plugins/plugin-dev/skills/hook-development/SKILL.md).

## 4. Subagents (Task → Agent tool)
Each subagent runs in its own fresh context window with a custom system prompt, tool subset, model override, and independent permission settings; intermediate tool calls stay inside it — **only the final message returns** to the parent as a tool result (https://code.claude.com/docs/en/subagents; https://code.claude.com/docs/en/agent-sdk/subagents). Definitions: `.claude/agents/*.md` (project) or `~/.claude/agents/` with YAML frontmatter `name, description, tools, model` (e.g. `sonnet|opus|haiku|inherit`), or built-ins — `general-purpose`, `Explore` (read-only), `Plan`, catch-all `claude`; most inherit the parent's permissions (https://code.claude.com/docs/en/sub-agents; https://code.claude.com/docs/en/agent-sdk/subagents). Up to ~10 parallel tasks, queued beyond that (https://www.ibuildwith.ai/blog/task-tool-vs-subagents-how-agents-work-in-claude-code/). `run_in_background` makes the task async with notifications; a `fork` starts from a copy of the parent conversation; `isolation: worktree` gives it its own checkout — both addressable via permission params `Agent(model:opus)`, `Agent(isolation:worktree)` (https://code.claude.com/docs/en/subagents; https://code.claude.com/docs/en/permissions). Originally "Task": the agent spawns a copy of itself with no further spawn ability, max one branch (https://minusx.ai/blog/decoding-claude-code/).

## 5. Context management
System prompt is dynamically assembled (~65 fragments, cache-boundary marker splitting static/dynamic halves) (https://y-agent.github.io/inside-claude-code/03-prompt-assembly.html; https://claude-code-explain.helmcode.com/system-prompt/). CLAUDE.md hierarchy, concatenated broad→specific: managed policy (`/Library/Application Support/ClaudeCode/CLAUDE.md`; `/etc/claude-code/CLAUDE.md` on Linux) → user `~/.claude/CLAUDE.md` → project `./CLAUDE.md`/`.claude/CLAUDE.md` → `CLAUDE.local.md` → subdirectory CLAUDE.md loaded lazily when files there are read; `@path` imports (https://code.claude.com/docs/en/memory; https://code.claude.com/docs/en/claude-md; https://dev.to/rulestack/which-claudemd-files-claude-code-actually-loads-and-in-what-order-3be0). Auto memory: agent-written `MEMORY.md`, first 200 lines/25KB injected each session (https://code.claude.com/docs/en/how-claude-code-works). Auto-compact triggers near the limit (threshold per model; override `/autocompact 500k`): it first **clears older tool outputs** (microcompaction-style context editing), then replaces history with a structured summary; it aborts with a thrashing error if context refills immediately (https://code.claude.com/docs/en/how-claude-code-works; https://code.claude.com/docs/en/context-window). Post-compact, CC re-injects root CLAUDE.md, unscoped rules, auto memory, the plan, re-reads up to 5 recently-modified files, and re-invoked skill bodies (5k tokens/skill, 25k total) (https://code.claude.com/docs/en/context-window).

## 6. Sessions, checkpoints, background
Every message/tool call/result persists as plaintext JSONL under `~/.claude/projects/`, enabling resume/fork/rewind (https://code.claude.com/docs/en/how-claude-code-works). `claude --continue`/`--resume` reopen the same session ID and append; `--fork-session`/`/branch` copies history into a new session ID; the `/resume` picker is worktree-aware (https://code.claude.com/docs/en/sessions). Checkpoints: a snapshot before **every user prompt** of files CC's editing tools touch; 100 most recent kept; `Esc Esc`/`/rewind` restores code, conversation, or both (symlinks skipped; remote actions not covered); "Summarize from/to here" = partial compaction (https://code.claude.com/docs/en/checkpointing; https://www.buildthisnow.com/blog/guide/mechanics/claude-code-checkpoints-rewind). Background: Bash `run_in_background`, the `Monitor` tool streaming each output line mid-conversation, session-scoped `Cron` scheduled tasks restored on resume, `PushNotification` (https://code.claude.com/docs/en/tools-reference).

## 7. Plan mode
A permission mode + a research phase: Claude reads files and runs read-only/gated commands but cannot edit source (https://code.claude.com/docs/en/permissions). Entered via Shift+Tab cycle, `/plan`, or the `EnterPlanMode` tool; built-in read-only Plan agent (https://dev.to/rulestack/claude-code-plan-mode-what-it-actually-blocks-what-still-runs-and-what-approving-switches-you-22m3; https://y-agent.github.io/inside-claude-code/19-plan-mode.html). Exit: the model calls **`ExitPlanMode`** — "present plan for approval and start coding (plan mode only)" (https://github.com/davccavalcante/claude-code-leaked/blob/64646773/src/tools/ExitPlanModeTool/ExitPlanModeV2Tool.ts) — offering "clear context and auto-accept edits" / "auto-accept edits" / "manual approvals"; on approval the `planContent` is injected into context and the session drops into `acceptEdits` (https://github.com/anthropics/claude-code/issues/26349; https://github.com/anthropics/claude-code/issues/39973). The plan itself re-injects from disk after compaction (https://code.claude.com/docs/en/context-window).

## 8. Skills, slash commands, MCP
Skills = `SKILL.md` + YAML frontmatter (`name`, `description`, optional `allowed-tools`, `model`, `disable-model-invocation`) living in `.claude/skills/`, `~/.claude/skills/`, plugins, or nested dirs (https://code.claude.com/docs/en/skills). Progressive disclosure: only name+description sit in context at session start; the body loads when invoked — by the model when relevant, or explicitly as `/skill-name`; custom slash commands (`.claude/commands/deploy.md`) are now merged into skills and create the same `/deploy` (https://code.claude.com/docs/en/skills; https://code.claude.com/docs/en/context-window). MCP servers (`.mcp.json`, user/project scopes) add tools named `mcp__<server>__<tool>`, permission-rule-addressable, with definitions deferred via tool search until used; per-tool `requiresUserInteraction` forces prompts (https://code.claude.com/docs/en/how-claude-code-works; https://code.claude.com/docs/en/permissions).

## CC signature behaviors
- Single main loop, flat message list — no orchestration graph, debuggable by design.
- One persistent bash process; cwd/env state carries across tool calls.
- Read output is line-numbered `cat -n` style; Edit demands prior Read + exact-unique `old_string` (else `replace_all` or Write fallback).
- Agentic ripgrep/file search instead of embeddings/RAG.
- Small Haiku-class model for sub-cognitive work (labels, parsing, summaries) — over half of all calls.
- Permission prompts whose "don't ask again" writes durable allow rules into settings files.
- Deny>ask>allow, first-match rule evaluation with subcommand-split Bash matching.
- Hooks as stdin-JSON shell commands; exit 2 blocks; JSON out can rewrite tool input or decide allow/deny/ask.
- TodoWrite: the model rewrites its own full todo state; empty-list `<system-reminder>` nudges.
- Subagents with virgin context returning only a final summary; per-subagent model/tools/permissions.
- Auto-compact near the limit: old tool outputs cleared first, then a structured summary; `/compact <focus>` and `/autocompact` overrides.
- Esc interrupts mid-tool; typed corrections queue and steer the next step.
- Esc-Esc rewind restores pre-prompt file snapshots (checkpoints beside git, not inside it).
- Plan mode: research-only until `ExitPlanMode` approval flips the session to acceptEdits.
- Prompt style: `<system-reminder>` XML, good/bad examples, and liberal IMPORTANT/NEVER emphasis.
