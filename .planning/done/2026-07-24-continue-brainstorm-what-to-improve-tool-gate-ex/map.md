# Wayfinder map: 2026-07-24-continue-brainstorm-what-to-improve-tool-gate-ex

## Destination

An evidence-based **go/no-go decision** on whether tool-gate's keyword recall is good enough in practice. Reach it by (1) defining what counts as a "miss", (2) instrumenting it from telemetry that already exists, (3) measuring it over real usage, (4) applying a pre-agreed threshold. If the verdict is **go** — tool-gate's matching is done for now, the extension ships as-is. If **no-go** — the measurement points at which fixes matter, and the fix-menu graduates from fog into a fresh effort (not this map).

This is a *decision* destination, not a feature destination: we measure first, invest second. The disciplined outcome "tool-gate is good enough — stop" is a legitimate, welcome resolution.

## Notes

- **Domain** — `bun-apps/pi-agent-ext-tool-gate/`: a token-optimization extension that gates heavy domain tools behind prompt keyword + noun∧verb co-occurrence matching, reactivating on keyword and keeping them sticky. Saves ~8,500 tok/req (~52%, measured; PR #778). Core pipeline: `updateSticky` (mutate) → `filterActive` (pure, fail-open) → `setActiveTools`; escape hatch = always-active `enable_tool`.
- **What's already settled (landed in #778, do NOT re-litigate)** — precision audit (S2 bare-word removal, `pi_deploy`/`cost`/`image`/`video` behind `requires`), `flux2`/`ltx` `want`/`need` intent verbs, `PRECISION_RISKS` complete (13), savings unified to a verifiable 8,500, hot-path regex cache, banner timer cleanup, dead-code removal, the cross-package `pi.events` guard. The code-review-driven improvement surface is **exhausted**; this map is the *next* axis (recall/observability), not more review cleanup.
- **The asset this map exploits** — tool-gate already EMITS per-turn telemetry (`emitToolGateLog`, `tool-gate.ts:418`) but **nothing consumes or aggregates it** (grep-verified: only the emitter + tests + README reference it; no `qa/miss-*`). Three event kinds: `turn` (`:551`), `miss_candidate` (`:558`), `activate` (`:606`/`:629`/:651 from `enable_tool`). Opt-in via `TOOL_GATE_LOG=1` (stderr) or `TOOL_GATE_LOG_PATH=<file>` (JSONL). Every `activate` carries a `ts` + `via` + `matchedGate` + `activated`, so a `miss_candidate` turn can be correlated to a *subsequent* `activate` in the same session by timestamp. This is a closed-loop signal built but not yet closed.
- **Why the obvious metric is wrong** — `isMissCandidate` (`tool-gate.ts:431`) = "prompt non-empty ∧ no gate fired ∧ ≥1 dormant gate". That fires on essentially every non-triggering prompt while any gate is dormant (e.g. "fix this typo" with `ltx` dormant) → a raw miss-candidate rate is near-100% on any diverse workload and means nothing. The metric needs sharpening before any measurement is worth running — this is ticket [01].
- **Cross-effort landscape** — `2026-07-20-brainstorm-code-review-bun-apps-pi-agent-ext-too` → **DONE** as PR #778 (the exhaustive code-review + fix pass that preceded this map). Do not re-open review findings here.
- **Scope chosen (grilling 2026-07-24)** — axis = recall/observability (over savings-push / semantic-matching-jump / open-exploration); destination shape = evidence-first go/no-go (over ship-a-dashboard / spec-a-fix); map scope = narrow-to-verdict (the conditional fix-menu is fog, not a live ticket). These three are the *map's definition*, not route steps — they live here, not in Decisions-so-far.
- **Skills every session should consult** — `wayfinder`, `grilling`, `grill-memory`, `domain-modeling`. Tickets [01]/[03]/[04] are grilling (HITL judgment); [02] is prototype; [05] is task.
- **Frontier shape** — [01] is the sole initial frontier (every other ticket depends on the metric definition). After [01] closes, [02]/[03]/[04] all unblock and may be worked in parallel (independent of each other). [05] unblocks only when [02] ∧ [03] ∧ [04] are all closed. Recommended: resolve [01] first; then parallelize [02] (build) + [03] (start the clock on real-usage collection early — it needs elapsed time) + [04] (set the bar).

## Decisions so far

- [01 — Define the recall metric](tickets/01-metric.md) — two-lens bundle, conditional on gated-domain sessions: **escape-rate** (headline friction: enable_tool calls / sessions that plausibly needed a gated tool) + **confirmed-miss** (gate-causation verdict driver: miss_candidate→activate by ts, per-gate breakdown). Scope = **gate-matching only** (model-proactivity separated to the fix-menu). Raw `miss_candidate` rejected as noise; task-broke deferred. The go/no-go bar (04) turns on the confirmed-miss lens, not raw escape-rate.
- [04 — Set the go/no-go threshold](tickets/04-threshold.md) — bar set cold: **GO iff zero confirmed-misses on common intents** (common = `MUST_FIRE` corpus); escape-rate descriptive-only (no ceiling, per 01's scope split). Fact-checked feasible: `miss_candidate` carries `promptHead`(80ch)+`dormantGates`, `activate` carries `matchedGate`+`intent` → classifiable; [02] must flag (not guess) unclassifiable. Absolute, not comparative (no pre-#778 baseline exists).
- [03 — Workload + timeframe](tickets/03-workload-timeframe.md) — **real usage, ~2 weeks, own sessions** (mid-window peek; extend / add `MUST_FIRE` floor if thin). **Logging ENABLED**: `TOOL_GATE_LOG_PATH=~/.pi/tool-gate/telemetry.jsonl` via `~/.zshrc` (marked lines 41–44; remove after verdict); local only, `promptHead`(80ch) of `miss_candidate` prompts. Verdict = *this user's* recall. Hand-off to [02]: no session-ID in telemetry → segment via `ts`-gap, flag if unreliable.
- [02 — Build the miss-rate aggregator](tickets/02-instrumentation.md) — **built `qa/miss-rate.ts` + `qa:miss`** (parse JSONL → segment by `ts`-gap → gated-domain detection → escape-rate + confirmed-miss per-gate + common/review labelling). 10 new tests, **213/213** suite, CLI smoke OK. No new instrumentation (01's "block, don't invent" honored); session-segmentation-via-`ts`-gap flagged for 05.
- [05 — Execute the measurement, record the verdict](tickets/05-verdict-execution.md) — **GO: tool-gate ships as-is.** 7-day mid-window peek (2026-07-26→08-02, no gaps); escape-rate 30.8% (4/13 gated-domain sessions — friction, descriptive-only); 22 confirmed-misses, **0 on common intents** — but the tool's `common=0` is tautological (substring≠word-boundary, module STATUS caveat), so the bar is re-met by manual HITL classification of all 22 prompts (every one a vague carry-over or non-domain phrase, none a recognizable video/img-gen intent). Fix-menu fog does NOT graduate (no-go-only); survivorship caveat stands open (out of scope).
