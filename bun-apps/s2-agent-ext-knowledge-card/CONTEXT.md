# s2-agent-ext-knowledge-card

The ubiquitous language of s2-agent-ext-knowledge-card — Zettelkasten knowledge management: distill markdown into atomic notes, CRUD over the vault, and graph-enhanced RAG, each backed by an isolated subagent; plus a deterministic convergence sink that dissolves per-workflow knowledge silos into one shared graph.

## Language

### Atomic notes

**Zettel card**:
An atomic, structured note in the vault — frontmatter (12-key record) + body + wiki-links + tags. The unit of the knowledge graph.
_Avoid_: note, card, document (it is an atomic zettel with a fixed frontmatter schema)

**MOC** (Map of Content):
The auto-generated index note that lists cards by tag/topic — the graph's table of contents, regenerated by `graph_health fix`.
_Avoid_: index, summary, table of contents (it is a navigational index note)

**Canonical id**:
The dedup key for deterministic ingest — re-ingesting the same record upserts the card in place rather than duplicating.
_Avoid_: record id, key (it is the stable cross-ingest identity)

### Ingestion

**Two ingestion modes**:
The two write paths into the graph — LLM distill (`zk_extract`) for free-form text, deterministic ingest (`zk_ingest`) for structured records.
_Avoid_: import modes, input types

**LLM distill** (`zk_extract`):
The ingestion mode backed by an isolated `obsidian_distill` subagent — decomposes free-form markdown/text into atomic notes.
_Avoid_: extraction, parsing (it is LLM-driven decomposition, not parsing)

**Deterministic ingest** (`zk_ingest`):
The no-LLM, no-network ingestion mode — each structured `.knowledge.jsonl` record becomes one card (dedup'd by canonical id, cross-linked by tags, MOC-indexed).
_Avoid_: import, bulk load (it is deterministic convergence, lossless + idempotent)

**Convergence sink**:
`zk_ingest`'s role — dissolves per-workflow `.knowledge.jsonl` silos into ONE shared, queryable, backlinked graph so `zk_ask` can answer cross-source questions.
_Avoid_: merge, aggregator (it is a convergence point that preserves identity + cross-links)

**Source family** / **adapter**:
The input shape + parser selected by `zk_ingest`'s `source` param — `workflow-jsonl`, `hermes`, `auto-memory`, or `generic` (the universal any-`.md` adapter).
_Avoid_: format, parser (a source family is a named input contract; the adapter implements it)

### CRUD

**`zk_card`**:
CRUD over zettel cards — `add` (4-layer duplicate check), `find` (multi-strategy), `update` (smart-merge), `remove` (backlink-safe), `check` (vault health audit).
_Avoid_: note tool, db tool

**4-layer duplicate check** (`add`):
The add-time guard — title / body / tags / comparison layers; a near-duplicate is blocked (use `--force` to bypass, which tags the result `#duplicate-candidate`).
_Avoid_: dedup, duplicate detection (it is a layered guard with a force-bypass audit trail)

**Backlink-safe delete** (`remove`):
`remove` aborts if inbound wiki-links exist (would orphan the linkers) unless `force` is passed.
_Avoid_: delete, purge (it is a link-aware deletion guard)

### Retrieval

**Graph-enhanced RAG** (`zk_ask`):
The retrieval pipeline over the vault — seed retrieval → N-hop wiki-link graph expansion → cluster & rank → tiered context assembly → synthesized answer with references.
_Avoid_: search, QA (it is a graph-augmented retrieval-and-generation pipeline)

**Seed retrieval**:
The first `zk_ask` stage — fuzzy title + tag + body keyword strategies, with a quality gate that rewrites the query once if the top seed scores below 0.4.
_Avoid_: initial search, query (it is the multi-strategy seed for graph expansion)

**Two read paths**:
The two retrieval surfaces — `retrieveRecords` (deterministic, no LLM, powers `knowledge_query`) vs `zk_ask` (graph-enhanced RAG, LLM-synthesized). The P1 callout boost is `retrieveRecords`-only.
_Avoid_: query modes, read modes

**`knowledge_query` / `graph_health`**:
The hub's direct no-LLM surface — wrapping `src/retrieve.ts` with no subagent, no model, no network. A cheaper fast read/audit path than the `zk_*` tools.
_Avoid_: lite tools, helpers (they are first-class deterministic tools, not utilities)

### Architecture

**Task builder** (`buildDistillTask` / `buildAddTask` / …):
The single source of truth for each tool's subagent task — shared with `s2-agent`'s `zk-*` commands so the CLI and extension never drift.
_Avoid_: prompt builder, task factory (it is the shared contract between CLI + extension)

**Allowlist** (`DISTILL_TOOLS` / `ADD_TOOLS` / …):
The per-action tool set each subagent may call — pinned by a cross-package contract test that loads the real pi-obsidian extension and asserts every named tool is registered.
_Avoid_: tool list, permissions (it is a tested per-action tool contract)

### Distill pipeline (folded into zk_ingest)

**Distill actions** (`zk_ingest` `action=gate|converge|status`):
The agent-self-triggered hermes-memory bloat reducer, surfaced as actions on
`zk_ingest` (no separate tool). `gate` deterministically filters raw entries;
enrichment happens in the driving agent's reasoning turn; `converge` writes via
`ingestRecords` + supersedes raw cards + adjusts the adaptive threshold.
_Avoid:_ distill tool (it is zk_ingest actions, not a tool).

**Survivors / Killed**:
Gate outputs — survivors are entries that passed (dedup/stale/malformed filter,
each with a reason), ready for in-context enrichment; killed are the rejected
entries (reason: duplicate/stale/malformed).
_Avoid:_ kept/passed, rejected/filtered.

**EnrichedNote**:
The agent-enriched shape handed to converge — id/type/title/detail/tags,
optional dimension/confidence/supersedesCardId.
_Avoid:_ note, card (it is the enriched-shape input to converge).

**DistillState**:
Per-vault pipeline state — adaptive threshold (N ∈ [20,200]) + run history +
lastRun. Read via `action=status`; converge adjusts the threshold from killRate
+ passRate (high kill+pass → −5; low pass → +10; else stable) and persists.
_Avoid:_ config, settings (it is the distill run-state + threshold + history).
