# Archify — Deep Integration Audit (Receipt)

- Date: 2026-07-25
- Scope: bun-apps/s2-agent-ext-archify/
- Spec: .planning/specs/2026-07-25-archify-deep-audit-design.md
- Mode: Read-only charter (no code changed)

## Overall verdict
The thin-bundle integration is clean where it actually runs: vendored `.mjs` is spawned (not imported) so 1.5 MB stays out of the bundle, the abort/`shell:false`/no-PATH signal contract is sound, all 3 tools pass `checkToolContract`, and schema cost (515 tokens) is mid-pack among siblings. **One Critical defect offsets this:** under the DEFAULT deploy mode (`deploy-bundle`), `scripts/deploy.ts` never copies `vendored/` next to the thin bundle, so `VENDORED_BIN` resolves to a nonexistent path and all three tools silently die with `Cannot find module` at runtime — invisible to the test suite (which imports `lib/*.ts` directly) and to the schema-cost canary (which is itself currently hard-failing in this worktree for unrelated dep reasons). Secondary risks are a misleading error message that blames IR validity for the missing bin, and stale schema-cost baselines that leave archify's 515-token floor un-regression-guarded.

## Cross-dimension notes

- **Spawn seam agreement (D1 vs D2 vs D5):** All three dimensions independently confirm `lib/run.ts:24`'s `spawn(process.execPath, [VENDORED_BIN, ...])` is the single seam between the extension and the vendored binary. D2 confirms it structurally guarantees 686 KB stays out of the bundle (no import edge for the bundler to follow); D5 confirms exactly 3 subcommands (`validate`/`deliver`/`compare`) cross that seam. The D1 Critical finding (VENDORED_BIN unresolved under deploy-bundle) is therefore the load-bearing risk for ALL three dimensions — a broken path doesn't change what is/isn't bundled, but it makes the spawned binary unreachable at runtime. **Resolution: keep the Critical severity on D1 F1; D2/D5 findings stand as record-only confirmations of the design intent that the broken path defeats.**
- **Schema numbers agreement (D3 vs D4):** Both dimensions measured 515 tokens (render=213 / validate=160 / delta=142) via the same `buildSchemaCostReport` builder (D3 via `bun -e`, D4 via `createCapturingApi`). Numbers reconcile exactly; de-duplicated into a single Info row per dimension (D3 F1 mid-pack ranking, D4 F2 contract-cleanliness — complementary framings, both kept).
- **Canary CLI blocker (D3 F5 vs D4 F4):** Both dimensions hit the identical `@repo/s2-agent-ext-subagent` symlink gap in `s2-agent-ext-knowledge-card`. D3 frames it as "published UX broken" (Info); D4 frames it as "gate hard-fails with exit 1" (Important). **Resolution: the D4 framing is stronger (it is the gating precondition for the canary to fire AT ALL, not just a UX nit) — kept as Important (D4 F4); D3's mention folded into the same cross-note rather than carried as a separate finding.**
- **Baseline staleness (D3 F4 vs D4 F5):** These are two DIFFERENT baseline files. D3 F4 = `boot-smoke.baseline.json` `sourceMinimum` (archify absent from the expected-sources list — Important, regression floor). D4 F5 = `schema-cost-baseline.json` enforced totalTokens (archify absent from token totals — Important, will emit spurious >5% WARNING once the gate runs again). Both kept as separate Important findings because they guard different things.
