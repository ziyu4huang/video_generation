# Goal: Embed todo + ask_user_question into `pi-agent-ext-power-tool`

## Motivation

`@juicesharp/rpiv-todo` and `@juicesharp/rpiv-ask-user-question` were removed
as npm dependencies (next-goal-20260704_234808). But the `todo` and
`ask_user_question` tools are **not** built into pi-core — they only existed
through those npm packages. We need them back, but as **first-party code**
inside our own extension, not as an external npm dependency.

This eliminates:
- npm registry dependency (version drift, lockfile noise)
- i18n overhead (both packages bundle `rpiv-i18n` + `rpiv-config` for
  localization never used in the EN-only dev environment)
- extra context-window tax from unused locales + config layers

```

tool/response-envelope.ts ← buildToolResult()

state/state-reducer.ts  ← pure reducer: (state, action) → (state, op)

state/selectors.ts      ← pure derived queries

index.ts                ← ExtensionFactory (default export)
```

## Key adaptations

### 1. Drop `config.ts` + guidance file I/O

Both packages load a `guidance` section from a JSON config file at init
(`loadConfig()` → `validateGuidanceFields()`). We replace with hardcoded
`DEFAULT_PROMPT_SNIPPET` and `DEFAULT_PROMPT_GUIDELINES` arrays.

### 2. Drop `i18n-bridge.ts`

Both packages' `state/i18n-bridge.ts` wraps `@juicesharp/rpiv-i18n` with a
`t(key, fallback)` → `fallback` shim. We bypass the entire layer:

- `formatStatusLabel(status)` → inline in `view/format.ts` (3 entries)
- `displayLabel(kind)` → inline in `view` or `row-intent.ts`
- Overlay strings → hardcode English literals

### 3. Keep `pi-tui` dependency

Both packages use `@earendil-works/pi-tui` for:
- `Text` component (renderResult/renderCall return type)
- `truncateToWidth` text helper
- `TUI` type (widget registration)

This is **already available** as a workspace dependency — no change needed.

### 4. Keep `typebox` dependency

Already available — our `src/index.ts` already imports `Type from "typebox"`.

### 5. Keep `@earendil-works/pi-coding-agent` SDK

Already the foundation of the extension.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| `pi-tui` not available in headless mode | Guard `TodoOverlay` / view with `ctx.hasUI` check (already done in rpiv code) |
| Import paths break during copy | All `.js` → `.ts` extension; replace `../` import paths precisely |
| `StringEnum` import from `@earendil-works/pi-ai` | Keep the import — it's a valid SDK re-export; OR inline as `Type.Union(Type.Literal(...))` |
| Session replay / compaction broken | `replay.ts` and `store.ts` are unchanged — same `TaskDetails` shape, same `toolName: "todo"` |
| Overlay widget key conflict (`rpiv-todos`) | Keep `WIDGET_KEY = "rpiv-todos"` — changing it loses overlay state for existing users |
