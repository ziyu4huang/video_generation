These are `MD013` (line-length > 80) and `MD060` (table-column-style) findings in
documentation files. Markdown tables and inline code spans routinely exceed 80
columns; wrapping them degrades readability and the table style is intentional
padded-alignment for column alignment.

| File | Rule | Reason |
|------|------|--------|
| `README.md:12,19,21` | `MD013/line-length` | Prose lines with inline code/paths exceed 80 cols; wrapping mid-path hurts readability. |

## Rule-level notes

- **`MD013` / `MD060`** (markdownlint): the 80-column prose limit and compact-table
  preference conflict with readable tables and code-rich lines. These are
  documentation style preferences, not correctness issues — accepted project-wide.
- **`line_length` / `function_parameter_count` / `identifier_name`** (Swift):
  these ARE actionable and were fixed down from 13 → 0 in this session.
